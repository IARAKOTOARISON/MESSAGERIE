🔧 GUIDE DE DÉBOGAGE - Erreur Stéganographie

═══════════════════════════════════════════════════════════════

Si vous obtenez le message:
"❌ Erreur lors du téléchargement de l'image"

Suivez ce guide de débogage pas à pas!

═══════════════════════════════════════════════════════════════

✅ ÉTAPE 1: Tester la stéganographie

═══════════════════════════════════════════════════════════════

1. Connectez-vous sur le site (si vous ne l'êtes pas)

2. Allez à cette URL:
   http://localhost/projects/MDI/cyber-securite/messagerie/codes/fake_login/test_steghide.php

3. Vous verrez un rapport de diagnostic:

   ✅ Connecté en tant que...    → Doit être OK
   ✅ Dossier existe             → Doit être OK
   ✅ Dossier accessible         → Doit être OK
   ✅ Steghide trouvé             → Doit être OK
   ✅ Commande Steghide réussie  → Doit être OK


Si TOUS les tests sont ✅:
→ Le système devrait fonctionner! Essayez steganography.php à nouveau

Si un test est ❌:
→ Continuez avec les solutions ci-dessous


═══════════════════════════════════════════════════════════════

❌ SOLUTION 1: Dossier non accessible en écriture

═══════════════════════════════════════════════════════════════

Si vous voyez: "❌ Dossier NON accessible en écriture!"

Ouvrez un terminal et exécutez:

    sudo chmod -R 777 /opt/lampp/htdocs/projects/MDI/cyber-securite/messagerie/codes/uploads/

Puis rechargez la page de test.


═══════════════════════════════════════════════════════════════

❌ SOLUTION 2: Steghide non installé

═══════════════════════════════════════════════════════════════

Si vous voyez: "❌ Steghide NON trouvé!"

Ouvrez un terminal et exécutez:

    sudo apt-get update
    sudo apt-get install steghide

Vérifiez:

    steghide --version

Puis rechargez la page de test.


═══════════════════════════════════════════════════════════════

❌ SOLUTION 3: Erreur Steghide

═══════════════════════════════════════════════════════════════

Si vous voyez: "❌ Erreur Steghide:" avec un message

Lisez le message d'erreur:

ERREUR: "version `GLIBCXX_3.4.20' not found"
         "version `CXXABI_1.3.8' not found"
         "version `CXXABI_1.3.9' not found"
         "version `GLIBCXX_3.4.21' not found"
→ Solution: C'est un problème de bibliothèque XAMPP!
   Cette erreur est DÉJÀ CORRIGÉE dans steganography.php
   
   Si vous l'obtenez toujours:
   1. Videz le cache du navigateur (Ctrl+Shift+Delete)
   2. Rechargez la page complètement (Ctrl+F5)
   3. Essayez à nouveau

   Si ça ne fonctionne toujours pas, exécutez en terminal:
   LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:/usr/lib:/lib/x86_64-linux-gnu:/lib /usr/bin/steghide --version
   
   Cela doit afficher: steghide version 0.5.1

ERREUR: "buffer overflow detected *** terminated Aborted (core dumped)"
→ Solution: L'image n'a pas assez de capacité pour le payload!
   
   Steghide peut stocker environ 1 byte par 32 bytes d'image.
   Exemple: Image de 100KB peut contenir ~3KB de payload
   
   Le payload de phishing est généralement ~100 bytes,
   donc une image doit être au minimum ~3200 bytes (3KB)
   
   Solutions:
   1. Utilisez une image PLUS GRANDE (au moins 500KB)
   2. Vérifiez avec test_image_format.php
   3. Téléchargez une image depuis:
      - https://picsum.photos/1920/1280 (Gros fichier recommandé)


ERREUR: "le format du fichier n'est pas supporté"
→ Solution: Le fichier n'est pas une véritable image valide!
   Raisons possibles: 
   1. Fichier renommé (JPG renommé en PNG)
   2. Image corrompu
   3. Image trop petite (< 100x100 pixels)
   
   Solutions:
   1. Allez à: test_image_format.php
      http://localhost/projects/MDI/cyber-securite/messagerie/codes/fake_login/test_image_format.php
   
   2. Uploadez votre image et vérifiez:
      - Les dimensions sont >= 100x100
      - Le format est JPG ou PNG
      - Le fichier n'est pas corrompu
   
   3. Si problème persiste, téléchargez une nouvelle image:
      - https://picsum.photos/800/600 (JPG recommandé)
      - https://loremflickr.com/800/600 (JPG)
      - https://via.placeholder.com/800x600 (PNG)

ERREUR: "Cannot open file for writing"
→ Solution: Dossier uploads/images/ n'est pas writable (voir SOLUTION 1)

ERREUR: "All capacity is used"
→ Solution: L'image est trop petite pour le payload
   Utilisez une image plus grande (au moins 200x200 pixels)


═══════════════════════════════════════════════════════════════

❌ SOLUTION 4: Image trop petite

═══════════════════════════════════════════════════════════════

Si vous uploadez une image TRÈS petite (< 50KB):

Essayez une image plus grande:
- Minimum: 200x200 pixels
- Recommandé: 800x600 pixels ou plus

Téléchargez une image depuis:
- https://picsum.photos/800/600
- https://loremflickr.com/800/600


═══════════════════════════════════════════════════════════════

❌ SOLUTION 5: Apache/PHP ne fonctionne pas

═══════════════════════════════════════════════════════════════

Si vous obtenez une erreur 500 ou la page ne charge pas:

1. Démarrez XAMPP:
   sudo /opt/lampp/manager-linux-x64.run

   Ou depuis le terminal:
   sudo /opt/lampp/lampp start

2. Vérifiez que Apache fonctionne:
   sudo /opt/lampp/lampp status

3. Réessayez

✨ TEST MANUEL (Sans site web)

═══════════════════════════════════════════════════════════════

Si vous voulez tester Steghide directement:

1. Créez une image de test:
   wget https://picsum.photos/800/600 -O test.jpg

2. Créez un fichier payload:
   echo "<script>alert('Bonjour')</script>" > payload.txt

3. Exécutez la commande Steghide:
   steghide embed -cf test.jpg -ef payload.txt -sf output.jpg -p '' -f

4. Vérifiez:
   ls -la output.jpg

Si ça fonctionne, le problème vient du site web.
Si ça échoue, le problème vient de Steghide.
